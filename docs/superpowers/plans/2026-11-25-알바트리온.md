# 알바트리온(가칭) 고난이도 레이드 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 화·수·뇌·빙 4속성 직업 4인이 속성 순환·억제 게이지·에스카톤 전멸기로 싸우는 고난이도 레이드 몬스터와, MVP 보상 룰렛 아이템(한 릴 역린)을 추가한다.

**Architecture:** 속성 기믹은 새 모듈 `handlers/레이드/알바트리온.js`(순수 함수)에 두고 `전투.js`에는 직업 세트 선택과 몇 개의 훅만 단다. 기존 몬스터 동작은 바꾸지 않는다. 몬스터 데이터는 `Monster/알바트리온.json`(처음엔 `enabled: false`), 보상 아이템은 `블랙월게이트웨이.js`와 같은 구조의 새 모듈로 만든다.

**Tech Stack:** Node.js(CommonJS), discord.js 14, 자체 그림판(`handlers/레이드/그림판.js`, `그림.js`). 테스트 프레임워크 없음 — `assert(cond, msg)`가 ✅/❌를 출력하고 실패 시 `process.exitCode = 1`로 두는 일반 node 스크립트(`tests/raid/`, `tests/상호작용/`).

**Spec:** `docs/superpowers/specs/2026-11-25-알바트리온-design.md` (아이콘 원본: `docs/superpowers/specs/assets/알바트리온-아이콘-확정.json`)

**코드에서 확인해 둔 사실 (줄 번호는 이 시점 기준이고 바뀔 수 있으니 함수 이름으로 찾는다):**
- `handlers/레이드/전투.js`: `ROLES`(56)는 `sword/archer/tank/healer` 4개, `ROLE_ORDER`(76), `ACTIONS`(78: attack/skill/guard/potion), `PLAYER_MAX_HP = 100`, `GUARD_DAMAGE_RATE = 0.3`(방어하면 받는 피해 ×0.3), `HEALER_HEAL = 20`, `POTION_HEAL = 45`, `POTIONS_PER_BATTLE = 2`, `PARTY_BASE_SIZE = 4`, `HP_MIN_PARTY = 2`. 몬스터는 `Monster/*.json`을 `loadMonsters()`가 읽고 `monsterProblems(m)`(118)로 검증해 문제 있으면 건너뛴다. `enabled:false`는 `MONSTERS`/`HARD_MONSTERS`에서 빠지지만 `ALL_MONSTERS`·`loadMonsters()`에는 남는다(테스트 서버 소환·시뮬용).
- `createBattle(monster, party, rng, { minParty, boss })`(367)가 `battle`을 만든다. `resolveTurn(battle, rng)`(639)의 순서: 1) 아군 행동(`ordered`는 `ROLE_ORDER`로 정렬, 역할별 `m.role === '…'` 분기가 하드코딩) → 독·즉사 → 전멸 판정 → 2) 몬스터 행동(`const move = battle.monster.moves[battle.intent]`, `hit()`가 피해 계산: 취약·방어·도발 순) → 도발 반격 → 3) 분노 전환 → `pickNextIntent`(300) → `assignMarks` → 쿨타임 감소 → `battle.turn++`. 결과는 `'clear' | 'wipe' | null`. 그림용 데이터는 `battle.lastTurn`(`last`)에 쌓는다(`acts`, `hits`, `effects`, `monsterMove`, `monsterMoveKey`, `monsterFx`).
- 필살기 키 `smash`는 모든 몬스터가 반드시 가진다(`REQUIRED_MOVES = ['attack','smash']`). 알바트리온은 `smash`를 **에스카톤**으로 쓰고, `pickNextIntent`의 5턴 필살기 규칙은 `battle.alat`가 있으면 건너뛴다.
- `handlers/레이드/index.js`: 모집 화면 `recruitView`(242), 역할 버튼 customId `raid:role:<키>`, 시작 `raid:start`, 모집 마감 `onRecruitEnd`(875: 0명이면 `finishRaid(r,'noshow')`, 아니면 `startBattle`), `startBattle`(913), 보상은 `finishRaid` 안(~1034: MVP는 `contribution`으로 고르고, `mvpItem === 'gateway'`면 게이트웨이를 주고 해킹 툴은 안 줌). 진행 중 레이드는 `saveActive(r)`로 `DB/raid.json`에 저장되어 재시작 뒤 이어간다 — 그래서 `battle.alat`는 평범한 JSON이어야 한다.
- `handlers/레이드/그림.js`: 픽셀 아트는 `{ rows, palette }`(`'.'`는 투명)와 `drawPixels(sp, cx, cy, px, { dim, colors })`(196), 직업 아이콘 `ROLE_SPRITES`(224)·`roleIcon`(264)은 지금 16×16이고 `ROLE_ICON_PX = 3.4`(≈54px). 카드 4칸의 x 위치는 인덱스 × 219(+121.5)라 4직업이면 그대로 쓸 수 있다.
- `handlers/게임/블랙월게이트웨이.js`: 보유량 모듈의 기준 모양(서버별 `{ guildId: { userId: 개수 } }`, `DB/gateway.json`, `grantGateway`/`useGateway`, 앱 이모지 등록 함수). 역린은 이걸 복사해 만든다. 루트 `index.js`의 `loadGateways()`(364행)에서 시작할 때 불러온다.
- `handlers/게임/룰렛.js`: 하루 1회, 베팅 `BET_PRESETS`, `rollSpin(bet)` → `{ reels, multiplier, kind, symbol, payout }`(`kind`: `none`/`two`/`triple`), 결과는 `revealSpin(channel, message, lobby, bet, spin, hacks, prevReels)`로 채널에 공개, 꽝이면 `offerHack`(본인에게만 보이는 확인 + `HACK_PROMPT_MS` 타이머)이 뜬다. 테스트 서버는 `hackUnlimited(guildId)`로 아이템이 줄지 않고 XP 정산도 생략(`isTestGuild`).

**내가 정한 값(사용자가 승인한 설계 문서 안에서 구현자 재량으로 둔 것, 밸런스 시뮬로 조정):** 게이지 최대 100, `ATTACK_GAIN 6`, `SKILL_GAIN 15`, `DRAGON_EFF 1/3`, 에스카톤 피해 = 최대 HP의 60%(방어 ×0.3, 프로스트 월 ×0.6), 사이클 10~12턴, 속성 구간 1~3턴, `baseHp 14000`, `damageRate 0.8`. 직업 스킬 이름(플레임 버스트·아쿠아 웨이브·체인 라이트닝·프로스트 월)은 임시. 수 직업은 기존 치유사와 같은 스킬(전원 +20, 부활 25), 뇌 직업은 기존 궁수 스킬, 화는 검사 스킬(피해만 키움), 빙은 새 스킬 `frost`.

**사용자가 정한 것(바꾸지 말 것):** 직업 이름 대신 🔥💧⚡❄️ 이모지 표시, 직업 4종의 무기 컨셉(화염 대검/물 보석 지팡이/번개 삼지창/얼음 랜스+방패), 확정 아이콘(오라 50% 투명·무기 전체 둘레), 파티클·뱃지·글로우는 쓰지 않음, MVP만 역린 1개(최대 1개), 한 릴 재회전, 4속성이 다 모여야 시작, 상성 고리(화←수←뇌←빙←화), 에스카톤 2~3회에 끝나는 HP, 용 속성은 무작위 등장·낮은 효율로 게이지 상승.

**남은 열린 항목:** 몬스터 외형(스프라이트)·이름은 가칭/임시, 직업 스킬 이름 임시, 역린 이름('역린')·이모지('🔁') 임시. 이런 값은 나중에 사용자가 바꾸기 쉽게 상수/JSON 한 곳에만 둔다.

**막히면:** 위 코드 사실과 어긋나는 점(줄 번호·함수 이름 변경, 테스트 실행기 위치 등)을 발견하면 임의로 설계를 바꾸지 말고 사용자에게 한 줄로 물어본다. 설계 문서와 계획이 충돌하면 설계 문서가 우선이다.

## Global Constraints

- 직업 이름(화염기사 등)은 화면에 쓰지 않는다. 모집 버튼·파티 목록·결과·로그에는 이모지 🔥💧⚡❄️만 표시한다. 내부 키는 `fire` / `water` / `thunder` / `ice`.
- 속성 5개: 화·수·뇌·빙·용. 상성: 화 몬스터는 수 직업이, 수는 뇌가, 뇌는 빙이, 빙은 화가 억제한다. 용 속성은 모든 직업이 억제 효율 1/3로만 올린다.
- 몬스터는 1~3턴마다 속성을 바꾸고(직전과 같은 속성은 연속 불가), 약 10~12턴(무작위)마다 에스카톤 저지먼트가 온다. 게이지 최대 100을 채웠으면 버틸 수 있는 고정 피해만 들어오고, 못 채웠으면 4인 파티 전멸. 에스카톤이 끝나면 게이지 0으로 새 사이클.
- 모집: 속성 4개 중 하나를 고른다, 중복 불가, 4속성이 모두 차야 시작(본서버). 테스트 서버(`isExcludedGuild`)는 인원이 모자라도 시작할 수 있다.
- 몬스터 HP는 억제 게이지와 별개이고, 평균 에스카톤 2~3번(약 25~35턴)에 쓰러지게 맞춘다.
- 보상: MVP만 역린 1개, 최대 보유 1개, 서버(길드)별 보유. 한 릴 재회전은 룰렛 결과 직후 본인에게만 버튼이 뜬다.
- 출시 전에는 `Monster/알바트리온.json`에 `"enabled": false`를 둔다(테스트 서버에서만 `loadMonsters()`로 소환).
- 새 의존성 금지. 커밋은 사용자가 정한 규칙을 따른다: 테스트가 통과한 뒤 커밋하고, rule-guard가 확인을 요구하면 사용자에게 승인받는다. 푸시는 하지 않는다.
- 이모지 외에 아이콘 그림은 32×32 격자(28×28을 가운데에 놓음), 오라는 불투명도 50% 알파 합성.

## Review Focus

- 4명 미만으로 시작한 테스트 서버 전투(속성 담당이 없는 속성): 게이지를 못 올려도 NaN·크래시 없이 에스카톤 실패(전멸)로 끝나야 한다. → Task 3 테스트.
- 속성 담당자가 쓰러져 있을 때: 쓰러진 사람은 게이지를 올리지 못하고, 에스카톤은 살아 있는 사람에게만 적용되며, 수 직업의 부활 후 다시 게이지를 올릴 수 있어야 한다. → Task 3 테스트.
- 서버 재시작: 저장된 전투(`battle.alat`)를 JSON으로 직렬화·복원한 뒤에도 `resolveTurn`이 이어져야 한다. → Task 3 테스트.
- 모집: 같은 속성 중복 선택은 막고, 이미 참가한 사람이 속성을 바꾸면 자리만 옮기며, 모집이 끝났을 때 4명 미만이면 시작하지 않고 `noshow`로 끝나야 한다. → Task 4 테스트.
- 역린: 연타(같은 확인 메시지를 두 번 클릭)해도 한 번만 처리하고, 보유 0개면 버튼이 안 뜨며, 시간이 지나면 결과가 확정되고, 재회전 결과가 더 나빠도 XP 정산이 차액(음수 포함)만큼만 이루어져야 한다. → Task 7 테스트.
